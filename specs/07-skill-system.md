# 07 · 技能系统

## 定位

技能是"按需展开的操作手册"：平时只占一行摘要，命中触发词才把正文塞进上下文。用于在不撑爆上下文的前提下沉淀固定流程。

边界：本模块管技能的存储、检索与提示词注入，不负责技能内部流程的执行。

## 设计

一条技能包含两部分：

| 部分 | 字段 | 注入时机 |
|---|---|---|
| 摘要 | `summary` | 常驻系统提示词 |
| 正文 | `content` | 命中 `trigger_words` 后展开 |

**为什么要两段式**：把所有技能正文常驻提示词会随技能数量线性膨胀，而绝大多数技能在一次对话里根本用不上。

匹配规则：用户输入包含任一触发词即视为命中，命中后把该技能的 `content` 追加到本轮上下文。

## 契约

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/skill/page` | 分页 |
| POST | `/api/v1/skill/create` | 新建 |
| POST | `/api/v1/skill/update` | 全量更新 |
| POST | `/api/v1/skill/delete/{skillId}` | 删除 |

字段约束：

| 字段 | 约束 |
|---|---|
| `skill_code` | 用户内唯一（`UNIQUE(user_id, skill_code)`），小写字母数字加下划线 |
| `summary` | 不超过 200 字 |
| `content` | 不超过 8000 字符，超出拒绝保存（`SKILL_CONTENT_TOO_LONG`，8003） |
| `trigger_words` | 逗号分隔，最多 20 个，匹配为忽略大小写的包含判断 |
| `enabled` | 关闭则不参与匹配 |

## 关键流程

```
用户输入
  ├─ 1 加载全部 enabled 技能
  ├─ 2 摘要列表注入系统提示词
  ├─ 3 输入命中触发词 → 展开对应正文
  └─ 4 未命中 → 只有摘要，正文不占用上下文
```

## 取舍

| 选择 | 换来什么 | 代价 |
|---|---|---|
| 两段式渐进披露 | 上下文占用与技能数量解耦 | 触发词没写好会漏召 |
| 触发词简单包含匹配 | 零依赖、可预测 | 无法做语义召回 |
| 技能存库而非文件 | 页面可直接增删 | 版本管理交给 `updated_at` |
| 不做技能内子流程编排 | 实现简单，行为可预测 | 复杂流程需拆成多个技能 |

## 约束

- 技能正文不得超过 8000 字符，超出拒绝保存。
- 单次对话最多展开 3 个技能正文。
- 技能内容不得包含密钥等敏感信息。

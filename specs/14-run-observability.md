# 14 · 运行可观测

## 定位

把"Agent 怎么跑的"渲染成人能读的时间线：一次运行里模型想了几轮、调了什么工具、花了多少 Token、为什么停下——全部可见；跑完还能像录像一样回放。

边界：本模块只做**查看与控制**（列表、详情、时间线、回放、中断），不重跑、不改写历史；事件的生产与落库归 spec 02，运行状态机归 spec 05。

## 设计

### 页面结构

```
┌──────────────┬────────────────────────────────────────┐
│ 运行列表      │ 运行详情                                │
│ 过滤：状态 /  │  头部：状态 Tag + 模型 + 耗时 + Token    │
│  会话 / 时间  │  分段切换：时间线 | 工具链 | 用量        │
│ 行：时间、会  │                                        │
│  话、状态、   │  时间线：按 seq 升序的事件块             │
│  耗时、Token  │  ├ 思考块（可折叠，含耗时）              │
│ 分页          │  ├ 正文块（Markdown 渲染）              │
│              │  ├ 工具卡（名称 + 状态 + 耗时 + 参数/输出）│
│              │  └ 模型调用行（轮次 + 用量 + 耗时）       │
│              │  底部：回放控制条（播放/暂停/速度/进度）  │
└──────────────┴────────────────────────────────────────┘
```

### 事件渲染模型

前端把已落库事件按类型折叠为四类块，与事件流（spec 02）一一对应：

| 事件 | 渲染 |
|---|---|
| `thinking.delta` | 思考块（连续合并，展示字数与耗时） |
| `text.delta` | 正文块（Markdown 渲染，流式/回放同路径） |
| `tool.call`（start/end）+ `tool.result` | 工具卡：start 显示参数 JSON，result 显示输出与 `isError`；单帧超 4KB 截断并提示 |
| `model.call`（end） | 模型调用行：轮次、`durationMs`、`usage` |
| `run.result` / `run.exceed` | 产出块 / 达迭代上限提示 |
| `run.end` / `run.error` | 终态条：状态、`stopReason`、总用量、总耗时 |

同一 reducer 服务实时流与回放（`stores/run.ts`），保证两条路径渲染完全一致。

### 回放播放器

回放是"查看已发生的事"，**绝不重新执行**：

- 数据源：`GET /run/events/{runId}`（`afterSeq` 增量拉，单次 500 条封顶），一次拉全量后本地游标遍历。
- 控件：播放 / 暂停、速度档 `0.5x / 1x / 2x / 4x / 立即`、进度条（按 `seq` 比例）、跳转终态。
- 回放态视觉：顶部通栏提示条（`--lw-secondary-tint` 底）+ "返回实时"按钮；与工作台内嵌回放共用组件。

### 用量与统计

| 数据 | 来源 |
|---|---|
| 单次运行：输入/输出 Token、耗时、迭代数、停止原因 | `wb_run` 行（终态一次落库） |
| 工具调用次数与失败数 | 事件表（`tool.call` / `tool.result` 计数） |
| 运行趋势 / Token 趋势 / 工具分布 | `monitor/overview` 汇总（仪表盘复用） |

## 契约

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/run/page` | 运行列表，参数 `sessionId`（可选）`state`（可选）`from` / `to`（可选）`page` / `size`，仅当前用户 |
| GET | `/api/v1/run/detail/{runId}` | 运行详情，按 (runId, user) 校验归属 |
| GET | `/api/v1/run/events/{runId}` | 事件列表，`afterSeq` 增量，单次上限 500 |
| POST | `/api/v1/run/abort/{runId}` | 中断非终态运行 |

权限：全部登录即可用，归属由 `(runId, user_id)` 强制校验，不泄露他人运行。

## 关键流程

```
打开运行记录页
  ├─ 1 GET /run/page（默认全部状态，按时间倒序，骨架屏）
  ├─ 2 点行 → GET /run/detail/{runId} 渲染头部
  ├─ 3 GET /run/events/{runId} 拉全量事件 → reducer 折叠为块 → 时间线
  ├─ 4 非终态且有活动实例 → "中断"按钮可用；中断后收到/拉到终态帧
  └─ 5 点"回放" → 本地游标从 seq=1 重放已加载事件，不发起执行

从工作台跳到运行记录
  └─ 运行终态帧带 runId → 详情深链 /runs?runId=... 直接定位
```

## 取舍

| 选择 | 换来什么 | 代价 |
|---|---|---|
| 独立页面而非嵌在工作台左栏 | 有空间铺时间线/工具链/用量，排障时不被对话界面挤压 | 多一个路由与菜单项 |
| 回放用本地游标 | 不重新请求、不重新执行，播放零成本 | 回放粒度受已落库事件限制 |
| 事件块而非逐条事件流 | 人能读；噪声（心跳、合帧）不露出 | 需要一套稳定的折叠规则 |
| 服务端只提供原始事件 | 前端渲染自由演进，不改后端 | 折叠规则改了要回归前端 |

## 约束

- 时间线严格按 `seq` 排序渲染，前端不做重排与去重（`seq` 由服务端保证唯一递增）。
- 回放禁止触发任何写请求（abort 除外）；播放器只读本地数据。
- 运行详情、事件、中断必须按 `(runId, user_id)` 校验归属，查不到即 `RESOURCE_NOT_FOUND`。
- 工具输出超 4KB 单帧截断的展示以 `run.result` 与事件详情为准，前端提示"已截断"。
